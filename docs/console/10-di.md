# `call di` — DI scanner cache management

Manages the on-disk cache of classes discovered by the DI `Scanner`.
Mirrors the design of `mapping`: build, clean, show — same flow,
different cache file.

The cache file is at `Kernel::$pathStorageVolatile . '/di.php'`. Boot
loads it directly if it exists; otherwise it performs a live scan and
side-effect writes the cache.

**`DEBUG=true` disables the cache entirely**, forcing a live scan on
every boot.

---

## Synopsis

```
call di <command> [pattern]
```

| Command           | Purpose                                                |
|-------------------|--------------------------------------------------------|
| `build`           | Force-rebuild and write the DI cache file              |
| `clean`           | Delete the DI cache file                               |
| `show`            | List every class in the cache (or a live scan)         |
| `show <pattern>`  | Filter cached classes by FQCN substring (case-insensitive) |
| `<pattern>`       | Bare pattern is treated as `show <pattern>`            |

---

## `call di build`

Forces a fresh scan:

1. Unlinks the existing cache file (and invalidates opcache for it).
2. Runs `Scanner::run(rootDir: Kernel::$pathRoot, cache: $cachePath)`
   with `new DICollector(Container::init())` — the same call
   `BaseBoot::boot()` makes during normal startup.
3. Invalidates opcache again so subsequent loads see the new file.
4. Reports the discovered class count.

```bash
call di build
```

Sample:

```
 | [============ Di ============]
 |   di cache ............... [BUILT (1842 classes)]
 | [i] /srv/acme/storage/volatile/di.php
 | [============ Di ============]
```

Run this in your image build / deploy step alongside `mapping build`.

---

## `call di clean`

Deletes the cache file (and invalidates opcache). Boots after this run
fall back to live scanning.

```bash
call di clean
```

```
 |   di cache ............... [CLEANED]
```

If the file is already missing, the badge is `[NOT FOUND]` (no error).

---

## `call di show [pattern]`

Lists classes in the cache. If the cache file is missing, a **live
scan** is run via an in-memory `CollectorInterface` sink — same walk
the build would do, but without writing to disk.

```bash
call di show                  # everything (cache or live)
call di show App\Service      # FQCN substring filter
call di show service          # case-insensitive
call di service               # bare arg falls through to `show`
```

The filter is a plain `stripos()` against the FQCN.

Sample:

```
 | [============ Di ============]
 | [i] /srv/acme/storage/volatile/di.php
 | [ Matched 'Service' (24) ]
 |   App\Services\AuthService
 |   App\Services\BillingService
 |   App\Services\UserService
 |   ...
 | [ Matched 'Service' ]
 | [============ Di ============]
```

When no cache file exists, the listing is prefixed with:

```
 | [!] No DI cache file — showing live scan from /srv/acme
```

---

## Examples

```bash
call di build
call di clean
call di show
call di show App\Service
call di show Repository
```

---

## When to use what

| Situation                                  | Command           |
|--------------------------------------------|-------------------|
| Production deploy                          | `di build`        |
| Just added a new `#[Component]` class      | `di clean` (or rebuild) |
| "Is the container actually finding this?"  | `di show <fqcn-fragment>` |
| Auditing the DI surface                    | `di show`         |

Pair this with `mapping build` in your release pipeline — together they
move both controller scanning and DI scanning out of cold-start.
