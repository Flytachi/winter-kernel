# Db Console Command

The `db` console command manages database migrations and previews generated SQL for all PPA repositories discovered by the scanner.

```bash
call db ping
call db sql
call db migrate
```

Source: `console/Command/Db.php`.

---

## Commands

| Command | What it does |
|---|---|
| `ping` | Opens a connection per `DbConfig` and reports latency. Ignores `#[Migratable]` — pings every discovered config. |
| `sql` | Prints the SQL that `migrate` would execute, without running any statement. |
| `migrate` | Executes the SQL against each migratable database. Errors are reported per-statement; the run continues. |

---

## Flags

Flags select which statement categories are included. With **no flags**, all categories are included.

| Flag | Category | Notes |
|---|---|---|
| `-e` | Extensions | `CREATE EXTENSION IF NOT EXISTS …` — PostgreSQL only. |
| `-s` | Schemes | `CREATE SCHEMA IF NOT EXISTS …` — PostgreSQL only. |
| `-t` | Tables | `CREATE TABLE …` for every entity with `#[Table]` reached through a `#[Migratable]` config. |
| `-i` | Indexes | `CREATE INDEX …` emitted for table-level indexes. |
| `-c` | Constraints | `ALTER TABLE … ADD CONSTRAINT …` for foreign keys, checks, etc. |

Default execution order: extensions → schemes → tables → indexes → constraints. This order matters — `CREATE EXTENSION` runs first so that table `DEFAULT` expressions referencing extension functions (e.g. `gen_random_uuid()` from `pgcrypto`) resolve.

```bash
call db migrate              # all categories
call db migrate -t -i        # tables + indexes only
call db sql -e               # preview extension statements only
```

---

## Options

| Option | Effect |
|---|---|
| `--plugin=<name>` | Target a single registered plugin's namespace. |
| `--plugins` | Target every registered plugin. |
| _(no option)_ | Target the app root only. |

`ping` always pings the app **and** every registered plugin regardless of these options.

---

## Opt-in via attributes

`db sql` and `db migrate` are opt-in at the **DbConfig** level. A `DbConfig` class participates in migrations only if it carries `#[Migratable]`. This is intentional — `DbConfig` classes that point at legacy databases, read replicas, or vendor schemas are excluded from migration tooling by default.

```php
use Flytachi\Winter\Kernel\Ppa\Mapping\Attributes\Config\Migratable;
use Flytachi\Winter\Kernel\Ppa\Mapping\Attributes\Config\Extension;
use Flytachi\Winter\Kernel\Ppa\Mapping\Constants\MigratablePriority;

#[Migratable]                              // default priority: Normal
#[Extension('uuid-ossp')]
#[Extension('pgcrypto', cascade: true)]
final class MainDbConfig extends DbConfig { /* … */ }

#[Migratable(priority: MigratablePriority::Low)]
final class AnalyticsDbConfig extends DbConfig { /* … */ }
```

When two or more migratable configs are present, they run in priority order: `High` (0) → `Normal` (50) → `Low` (100). Within the same priority, order follows the scanner's discovery order.

### `#[Migratable]`

| Param | Type | Default | Purpose |
|---|---|---|---|
| `priority` | `MigratablePriority` | `Normal` | Migration ordering when multiple configs are migratable. |

A `DbConfig` without `#[Migratable]` is **silently skipped** by `db sql` / `db migrate`. The ORM still reads from and writes to it normally — only the migration tooling is gated. If a target has zero migratable configs the command prints a warning and continues to the next target.

### `#[Extension]`

Declares a PostgreSQL extension required by the database. Stack one attribute per extension; aggregated per `DbConfig` and emitted as `CREATE EXTENSION IF NOT EXISTS "name" [WITH SCHEMA s] [VERSION 'v'] [CASCADE]` during the `-e` phase.

| Param | Type | Default | Purpose |
|---|---|---|---|
| `name` | `string` | — | Extension name (e.g. `uuid-ossp`, `pgcrypto`, `postgis`). |
| `version` | `?string` | `null` | Pin a specific extension version. |
| `schema` | `?string` | `null` | Install into a named schema (`WITH SCHEMA …`). The schema must already exist. |
| `cascade` | `bool` | `false` | Auto-install required dependencies (`CASCADE`). |

`#[Extension]` is silently ignored for non-pgsql drivers — the structure object throws `InvalidArgumentException` if asked to render SQL for another dialect, but the Db command gates extension generation on `getDriver() === 'pgsql'` before that path is reached.

### `#[Table]` (entity-level)

`db sql` / `db migrate` walk repositories, resolve their entity class, and require the entity to carry `#[Table]` for column mapping. Entities without `#[Table]` are skipped — applies regardless of whether the surrounding `DbConfig` is migratable.

## Error handling

`migrate` catches `\Throwable` per statement. Known "already exists" SQLSTATEs are rendered as `EXIST` (warning yellow), other failures as `FAILED` (red). With `DEBUG=true` in `.env`, the underlying message is printed:

| Driver | "Already exists" codes recognised |
|---|---|
| `pgsql` | `42P06` (schema), `42P07` (table / index), `42710` (constraint) |
| `mysql` | `42S01` (table), `42000` (index) |

Extension statements use `IF NOT EXISTS`, so re-running `migrate -e` is a no-op when extensions are present — any other failure (missing package, denied privilege) reports as `FAILED`.

---

## Examples

```bash
call db ping                          # check connectivity to every config
call db ping --plugins                # include all registered plugins

call db sql                           # preview all categories for the app
call db sql --plugin=billing -t -i    # preview tables + indexes from one plugin

call db migrate                       # full migration for the app
call db migrate -e -s                 # extensions + schemes only (pgsql setup pass)
call db migrate --plugins             # migrate every plugin
```
